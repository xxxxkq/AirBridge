# 播放端点格式适配

## 处理方式

音频图内部仍为44.1kHz、PCM16、双声道。每个物理输出单独读取Windows当前共享模式MixFormat，优先保留其完整WAVEFORMATEXTENSIBLE头、有效位和声道掩码；在输出边界用NAudio已有的托管WDL重采样器进行采样率转换，再编码成设备接受的PCM8/16/24/32或32位浮点。单声道取左右平均，多声道只填前左/前右，其他声道静音；无法识别的编码/布局明确拒绝。该适配不改变系统格式、Codec、默认设备、手机连接或用户设置的输出延迟。

候选仅限系统混音格式、其等价标准头与原始输入格式，去重后逐个确认。只有格式不支持时尝试其他候选；占用、掉线等错误不通过换格式重试。每次初始化持有新的AudioClient，失败立即释放，不复用失败的初始化状态。

WDL的输出驱动模式会请求4个插值保护帧。适配器仅在最初提供这4帧零值（44.1kHz下约0.091ms），防止首次读取提前消费下一整个10ms图块；不增加手机抗卡顿缓冲。每个输出独立转换，图的原始块仍由多输出共享。没有变化的标准PCM16格式保持逐字节直通。

初始化错误显示设备名、格式和HRESULT；若设备声称支持MixFormat却在初始化时拒绝它，会提示检查设备连接或音频模式。保留原始异常供日志诊断。初始化候选/最终格式记录在数据目录output-format.log，单文件约1MB后保留一个备份；只在管理线程打开输出时写入，不在音频读写回调写磁盘。

## 2026-11-13 本机排查证据

- 历史本地日志在11月10日已有一次0x88890008（AUDCLNT_E_UNSUPPORTED_FORMAT），不是11月13日首次出现。
- AirPods重连前报告44.1kHz/32位浮点/双声道；查询支持，但原路径和新适配路径均初始化失败。绕过NAudio直接调用IAudioClient并去掉自动转换或事件标志，44.1/48kHz PCM/浮点尝试同样失败。
- 用户确认当时普通播放器也不能通过AirPods出声。用户自行在Windows重新连接后，端点报告48kHz/32位浮点/双声道，原路径与新路径均初始化成功。
- 本机AirPods、Realtek扬声器、显示器及两个VB-CABLE端点的新初始化均通过。测试未调用Play、未读取音频内容、未重连手机或改变三种默认输出角色。它证明初始化可用，不等同于实际音质/长期播放验证。

以上支持“蓝牙音频端点重连前状态异常”，但不能仅凭这些记录确定是休眠、驱动重连、音频模式还是其他组件触发。软件不自动重启蓝牙、不卸载驱动、不擅自改系统格式。

## 验证入口

```powershell
.\Build.ps1 -Configuration Development
.\Scripts\Test-Offline.ps1 -Release .\build\dev
# 实际端点探测：仅初始化再释放，不播放，不改默认输出。
.\Scripts\Test-OutputFormats.ps1 -RuntimeDirectory .\build\dev
```

32项纯PCM格式测试覆盖位深、有效位、单/多声道、一秒采样率比率、边界、有限回退和错误说明；21项图流水线测试包含48kHz与44.1kHz输出共享读取、暂停及恢复。原有缓冲和恢复套件继续运行。实际端点探测应在用户授权的排查中运行，不纳入自动离线测试。
