# 决策记录

记录日期为本次归档日期（2026-11-10），不是各项最初实现日期。依据现有源码和已确认需求整理；变更决策时追加替代记录，保留历史理由。

## ADR-001：C# + WPF 桌面，保留 C++ 采集（采用）

现有 Windows 界面与平台接口适合 C# / WPF，音频底层保留原生模块。迁移去掉运行时 PowerShell，降低脚本启动、异常及窗口身份管理成本；构建脚本仍可使用 PowerShell。暂不进行全 C++ 重写或跨平台 UI 迁移。

## ADR-002：不交付自研驱动，VB-CABLE 可选（采用）

自研声卡及 AAP 驱动涉及签名、安装权限、系统安全设置和维护成本，用户已停止此方向。保留 `Optional/` 研究但不构建、不安装、不随包分发。之后用户安装并验证了第三方 VB-CABLE，作为可选隔离端点接入；普通功能不得依赖其存在。Apple 原生控制能力不因有广播就视为支持。

## ADR-003：图管理音频路径，输入能力显式受限（采用）

手机独立通道可以进入处理图；电脑或应用原声若只做回环捕获，仍会从原路径播放。Windows原生应用路由用于直接改变目标，可选隔离端点用于效果链/多输出。Cable 已混合的声音不能再假装为彼此独立的应用流。变更路径须避免原声与转发重复播放。

## ADR-004：连接意图集中协调，手机按身份独立（采用，持续完善）

设备页、托盘和图是同一连接的多个控制入口，不应各建一份底层会话。`PhoneService`、`RouteCoordinator` 和引擎负责切换所有权；每台手机按身份分离采集，控制操作的串行化仅防止同一资源竞争，不能限制多手机同时存在。保留取消/释放屏障及故障诊断，不能仅增加重试掩盖旧会话问题。

## ADR-005：持久化接管日志与独立输出恢复（采用）

修改系统或应用输出前记录原值并确保恢复守护就绪；停止、退出或检测到主进程退出时按日志恢复。启动处理未完成恢复，避免应用崩溃后长期无声。不能承诺设备消失、权限变化、断电等所有情形都即时恢复，失败应可诊断并保留恢复记录。

## ADR-006：暂停无帧是等待，不自动重连（采用）

安卓暂停可正常零帧；重建通道可能暂停播放并影响其他蓝牙流。无帧单独不足以判定故障，不据此自动重连。缺音展示连续2秒无帧转等待，数据恢复重启观察窗口；保持连接意图，另用明确错误/设备事件处理真正断连。

## ADR-007：低延迟需要测量与有界策略（采用）

输入有界队列、异步诊断写入、按设备需求读取，分开统计实际补零、欠载事件及主动丢弃。有限丢弃加交叉淡化控制积压；自适应基于主进程收到 PCM 的间隔，包含采集和IPC抖动，不冒充蓝牙包到达时间。缓冲可升可降，关闭模式仍保留。输出低延迟改造需独立验证，不能以大缓冲宣称修好供给不足。

## ADR-008：设备数据如实展示（采用）

电量保留上次成功值及更新时间/过期信息；无数据 `—`。RSSI只以新鲜有效广播为卡片数值，缓存来源置于提示。佩戴检测为已适配型号的无驱动广播方案，有漏检及媒体控制局限。缺音率标识软件请求与收到音频的差额，主动丢弃单列，不代表射频丢包率。

## ADR-009：GitHub维护源码，日常不滚动建版本目录（采用）

`main`保存稳定源码，功能分支和小提交记录迭代；本地输出集中到`build/dev`，正式包进入 GitHub Releases。保留少量可回退版本，不为每次UI修改提升版本。阶段性发布统一更新版本、验证、打标签，代码与包能够对应。现有3.0.65是维护基线，不补造历史版本标签。

## ADR-010：编译隔离开发功能，正式版单EXE分发（采用）

Development定义AIRBRIDGE_DEVELOPMENT，Release从编译结果移除自检夹具、AB/输出对照和模拟故障。必要日志、恢复守护和真实手机工作进程保留。按明确文件清单内嵌正式运行组件，由单文件启动器校验并释放到内容寻址缓存；使用同一进程的新AppDomain运行，避免额外常驻启动器。此方式保持Framework/WPF和原生DLL兼容性，不为单文件迁移整个运行时。开机入口指向外层EXE，内部工作进程使用缓存组件。用户复制一个文件即可，但运行时仍有磁盘缓存，也仍需.NET Framework 4.8。

## ADR-011：GitHub检查显式启用，安装必须用户确认（采用）

自动检查默认关闭，不暗中访问GitHub。提供本次跳过、今日跳过、忽略指定标签、禁止更新；禁止更新阻断检查与下载。固定Release来源并校验SHA256/版本，先下载后由用户决定重启。临时安装进程等待现有音频与恢复结束再原子替换单文件，保留可回退文件；不常驻、不安装驱动、不自动提权。SHA256是完整性校验，不能代替独立发布签名。配置、日志、解包缓存和事务位于AppData，录音仍使用用户选定路径。

## ADR-012：用户可选便携或自定义数据根目录（采用）

扩展ADR-011的位置约束：AppData仅为兼容默认，不强制所有用户使用。软件旁XML保存位置选择，portable模式使用相对Data目录；配置、缓存和今后的更新统一跟随根目录。更改延迟到下次启动，等待输出恢复并校验复制，不删除旧数据、不合并已有配置、不搬录音或正在加载的缓存。位置待生效时禁止更新安装，以免混淆事务和恢复记录。单文件启动器与运行组件共用解析逻辑，避免更换目录后各进程写到不同位置。

## ADR-013：GPL-3.0源码公开（用户确认）

用户选择GPL-3.0，项目自有代码采用GPL-3.0-only。保留上游文件许可和NAudio的MIT声明，正式单文件内嵌GPL文本。公开前清理本机路径和真实测试地址；用户授权先备份再清理私有提交历史。历史备份仅存于被忽略的本机构建目录，不上传。开源准备不自动创建二进制Release或提高软件版本。
